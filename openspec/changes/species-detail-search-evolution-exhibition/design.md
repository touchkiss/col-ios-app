## Context

当前 BioScope 以首页卡片浏览为主，已有基本详情视图与分类探索页，但缺少可直接检索与时间维度叙事能力。数据层目前由 Data/MockData.swift 提供静态数据，导航由 ContentView.swift 中的自定义玻璃导航和 Tab 容器驱动，且全局风格为深色优先。

约束条件：
- 不引入后端与第三方依赖；
- 保持现有底部导航与首页交互主路径稳定；
- 复用现有 Species 模型与卡片组件，避免重复 UI 逻辑；
- 在小屏和大屏 iPhone 上保证滚动、点击和返回体验一致。

## Goals / Non-Goals

**Goals:**
- 构建信息完整、结构清晰的物种详情页，提升阅读与比较效率。
- 构建搜索页，支持按名称与标签进行实时过滤并跳转详情。
- 构建演化展览页，按历史年代分组展示多物种演化进程。
- 统一页面间导航行为（进入、返回、状态恢复）并保持现有架构可维护。

**Non-Goals:**
- 不接入网络 API、离线缓存、排序权重引擎。
- 不引入复杂全文检索能力（如拼音、模糊纠错、多字段加权）。
- 不重构现有首页动效架构与玻璃导航组件。

## Decisions

1. 页面结构决策：新增 SearchView 与 EvolutionTimelineView，详情页沿用并增强 SpeciesDetailView。
- 方案对比：
  - A. 在现有 TaxonomyExplorerView 上叠加搜索与时间轴；
  - B. 分离为独立页面。
- 选型：B。
- 理由：职责边界更清晰，便于分别演进搜索逻辑与展览叙事，不破坏现有 taxonomy 体验。

2. 数据组织决策：在 MockData 中新增“年代节点 + 物种关联”静态结构。
- 方案对比：
  - A. 在视图层临时拼装年代分组；
  - B. 在 Data 层定义可复用结构。
- 选型：B。
- 理由：避免视图逻辑膨胀，便于后续替换为服务端数据。

3. 搜索交互决策：采用前端即时过滤（本地数组过滤）+ 空态提示。
- 方案对比：
  - A. 提交式搜索（点击按钮后过滤）；
  - B. 输入即过滤。
- 选型：B。
- 理由：更符合移动端探索心智，且在当前小数据量下性能稳定。

4. 导航连续性决策：统一使用 Species 作为跳转载体，所有入口（首页、搜索、展览）进入同一详情页。
- 方案对比：
  - A. 每个页面维护各自详情展示；
  - B. 复用单一详情页。
- 选型：B。
- 理由：避免交互与视觉分叉，降低维护成本并提升一致性。

## Risks / Trade-offs

- [风险] 静态数据规模增大后本地过滤卡顿。→ 缓解：限制首版字段过滤范围（名称/标签），必要时引入分页或预索引。
- [风险] 展览页时间轴信息密度过高导致可读性下降。→ 缓解：按年代折叠分组，卡片信息分层展示。
- [风险] 多入口跳转详情造成返回路径感知不一致。→ 缓解：保持系统返回语义一致，不在详情页引入多分支返回逻辑。
- [权衡] 先保证结构与交互闭环，牺牲部分高级检索能力与可视化动画复杂度。

## Migration Plan

1. 数据层：扩展 MockData 的物种检索索引字段与演化年代分组数据。
2. 视图层：实现 SearchView 与 EvolutionTimelineView，并增强 SpeciesDetailView 信息分区。
3. 导航层：在 ContentView / Tab 映射中接入新页面入口，确保与现有 Tab 行为兼容。
4. 回归验证：执行搜索、跳转详情、返回、展览浏览与空态流程验证。
5. 回滚策略：若出现严重可用性问题，保留数据结构改动，临时隐藏搜索/展览入口并回退到现有探索页入口。
