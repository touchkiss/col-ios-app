## Context

当前项目为 SwiftUI iOS 应用，已存在自定义组件 `LiquidGlassTabBar` 与底部导航结构，但视觉层尚未与 iOS 26 的玻璃语言对齐。本次变更聚焦表现层升级，不改变路由、数据模型和业务流程。约束包括：
- 不新增第三方依赖，优先使用 SwiftUI 原生 Material/blur/overlay/mask。
- 在深色/浅色模式均需保证图标与文本可读性。
- 需要兼顾安全区、触控命中区域与滚动页面叠加场景。

## Goals / Non-Goals

**Goals:**
- 为底部 Tab 栏建立统一的 iOS 26 玻璃效果视觉规范。
- 定义选中/未选中状态在透明度、描边、高光和动画上的一致反馈。
- 在不同尺寸设备下保持布局稳定与交互可用性。
- 保留现有导航逻辑，确保 UI 升级可低风险上线。

**Non-Goals:**
- 不改动页面信息架构与 Tab 数量。
- 不实现新的业务交互能力（如手势重排、长按菜单）。
- 不引入全局主题系统重构。

## Decisions

1. 使用 `UltraThinMaterial` + 自定义渐变高光层构建玻璃底板，而非纯色透明叠层。
- 原因：Material 可提供系统一致的背景采样与动态模糊，结合渐变高光更贴近 iOS 26 视觉。
- 备选方案：纯 `Color.white.opacity(...)` + blur。未采用原因：层次感弱，深色模式可读性波动较大。

2. 通过单一样式配置对象（如常量组）集中管理透明度、描边、阴影与圆角参数。
- 原因：便于在浅色/深色模式下统一调参，减少散落 magic numbers。
- 备选方案：在各子视图内硬编码参数。未采用原因：维护成本高且难以统一体验。

3. 状态变化采用轻量动画（`easeInOut` 120-180ms）仅驱动颜色与高光强度，不做几何位移。
- 原因：保证反馈清晰且不影响导航稳定性。
- 备选方案：选中项放大/浮动动画。未采用原因：可能导致点击目标抖动与视觉干扰。

4. 保留现有 Tab 点击事件与容器结构，仅替换 `LiquidGlassTabBar` 的视觉实现。
- 原因：隔离风险，减少回归测试范围。
- 备选方案：重写整个 Tab 容器。未采用原因：超出本次范围。

## Risks / Trade-offs

- [低端设备渲染开销增加] → 控制叠层数量与阴影半径，优先使用系统 Material，避免多重离屏渲染。
- [深浅色模式对比不足] → 为图标与文字定义最低对比阈值并分别调参验证。
- [安全区与底部手势区冲突] → 在真机检查 Home Indicator 区域，确保额外底部内边距和触控高度。
- [与现有 Liquid Glass 组件风格偏差] → 复用命名与参数结构，统一视觉语义。

## Migration Plan

1. 在 `LiquidGlassTabBar` 内引入新玻璃样式层与状态样式参数。
2. 在接入层（如 `ContentView`）确认布局与 safe area 行为不变。
3. 进行浅色/深色、不同设备尺寸的手动回归检查。
4. 若出现可读性或性能问题，可回滚为旧样式实现（保留旧样式代码路径直至验收完成）。
