## Context

当前首页卡片主要是静态列表与基础点击跳转，缺少 App Store 风格的层级动效和连续过渡。此次变更聚焦首页 Tab 的卡片交互体验升级，覆盖三类核心动画：浮动（进入/滚动反馈）、点击（卡片到详情的连续过渡）、聚合（分组卡片合并与展开）。约束条件：
- 不改动现有数据模型与后端接口。
- 不引入第三方动画库，优先使用 SwiftUI 原生动画系统。
- 需兼容不同设备尺寸与“减少动态效果”可访问性设置。

## Goals / Non-Goals

**Goals:**
- 实现接近 iOS App Store 交互语言的首页卡片动画节奏和视觉层次。
- 保证卡片点击到详情的过渡连续性，减少跳变感。
- 为卡片分组场景提供聚合与展开动画，提升信息组织感知。
- 在低性能或辅助功能场景下提供可预测降级行为。

**Non-Goals:**
- 不变更首页信息架构与业务流程。
- 不新增推荐算法或内容分发逻辑。
- 不重写全局导航容器。

## Decisions

1. 使用 `matchedGeometryEffect` 驱动卡片到详情页的主视觉连续过渡。
- 原因：可在卡片与详情之间共享几何属性，获得系统级自然过渡。
- 备选方案：手动同步 frame/offset。未采用原因：维护复杂，边界场景抖动风险高。

2. 浮动效果采用“微位移 + 透明度 + 轻微缩放”组合，并与滚动位置弱耦合。
- 原因：在不分散注意力的前提下增强层次。
- 备选方案：强烈 3D 透视或大幅位移。未采用原因：干扰阅读且性能开销更高。

3. 聚合动画通过独立状态机管理（collapsed/expanding/expanded/collapsing），避免多布尔状态冲突。
- 原因：降低动画中断、重复触发和状态错乱概率。
- 备选方案：多 `@State` 组合。未采用原因：复杂场景可维护性差。

4. 动画参数统一抽离到首页卡片动效 token（duration/spring/opacity/scale/radius）。
- 原因：便于全局调参与浅色/深色、不同设备策略一致。
- 备选方案：分散硬编码。未采用原因：调优成本高且不可追踪。

## Risks / Trade-offs

- [动画叠加导致掉帧] → 控制同时动画元素数量，避免深层嵌套阴影与大面积模糊。
- [过渡中断导致 UI 状态错位] → 使用状态机和显式过渡阶段，关键切换点串行化。
- [Reduce Motion 场景体验不一致] → 提供无位移/短时淡入替代动画。
- [不同设备尺寸布局跳变] → 对小屏与大屏分别定义卡片间距、最大宽度和过渡锚点。

## Migration Plan

1. 在 `SpeciesCardView` 和首页列表容器中引入动效 token 与共享命名空间。
2. 接入点击过渡与聚合状态机，保留现有导航目标。
3. 增加 Reduce Motion 分支与小屏/大屏布局约束校验。
4. 回归测试首页滚动、点击、返回、分组展开/收起路径；若出现掉帧或交互冲突可回滚到静态过渡路径。
